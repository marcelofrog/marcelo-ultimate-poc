# JFrog Ultimate Bundle — End-to-End POC

A reference GitHub repository that demonstrates **JFrog's Ultimate bundle** — Curation, Xray, AppTrust, and Evidence — driving a real application from commit to production with policy-enforced promotion between lifecycle stages.

Everything is wired around a small FastAPI service. The point of the POC is not the app; it's the **flow** the app walks through:

```
                   ┌──────────────┐
                   │  developer   │
                   └──────┬───────┘
                          │  push
                          ▼
       ┌───────────────────────────────────┐
       │  GitHub Actions  (build workflow) │
       │                                   │
       │  1. Curation audit  ── blocks bad │
       │     packages before build         │
       │  2. Docker build & push  ───────► │──► JFrog dev-stage repos
       │  3. Create AppTrust app version   │
       │  4. Run tests + publish evidence  │
       └───────────────┬───────────────────┘
                       │
                       ▼
       ┌───────────────────────────────────┐
       │ Promote workflow   dev  ──►  qa   │  Gate: CVE ≥ 9 blocked
       │  (OIDC = dev-promoter identity)   │        Rego: tests passed
       └───────────────┬───────────────────┘
                       │
                       ▼
       ┌───────────────────────────────────┐
       │ Promote workflow   qa   ──► prod  │  Gate: CVE ≥ 9 blocked
       │  (OIDC = qa-promoter identity)    │        Rego: tests passed
       └───────────────────────────────────┘
```

Each arrow is enforced by JFrog. Each identity change is enforced by GitHub Environments + separate OIDC integrations. There is no way for a dev-stage credential to promote to `qa` or `prod`.

## What you get, in one screen

**Curation**
- Remote repositories for **PyPI**, **npm** and **Docker Hub**
- Three blocking policies: **malicious**, **no license**, **immature < 7 days**

**Users & permissions**
- Three service users: `<app>-dev-svc`, `<app>-qa-svc`, `<app>-prod-svc`
- Permission targets scoped to each stage's repositories only

**AppTrust**
- One AppTrust application (name prompted at setup time)
- `dev`, `qa`, `prod` repositories automatically created and bound
- Per-stage RBAC: `<app>-dev-svc` can write to the dev repo, promote nothing
- Promotion gates:
  - **Security gate** — block if any CVE ≥ 9.0 is *applicable* per contextual analysis
  - **Rego gate** — block unless the application version carries an evidence attestation showing ≥ N passing tests

**Application**
- FastAPI + uvicorn + pydantic + requests + httpx (all supply-chain-attack favourites)
- Docker image built from `python:3.12-slim` **pulled through the curated PyPI + Docker remotes**
- pytest suite whose result is published as a JFrog evidence attestation

**GitHub Actions**
- OIDC-only — no PATs, no long-lived secrets
- Three separate OIDC integrations, one per environment (`dev`, `qa`, `prod`)
- Build workflow: curation audit → docker build → app version → tests → **three signed evidence attestations** (test-results, docker image, SLSA provenance)
- Two promotion workflows, each protected by its own GitHub Environment, its own OIDC identity, and each producing a signed **promotion evidence** attestation
- All five evidence types use the same key generated by setup, so every stage transition is verifiable

## Quick start (5 steps)

1. **Install prerequisites** — see [docs/00-prerequisites.md](docs/00-prerequisites.md). You need `jf` CLI ≥ 2.60, `gh` CLI, `docker`, and admin Web UI access to a JFrog instance with Ultimate license.
2. **Register a JFrog CLI profile — this is the only auth step in the entire POC.** Every script derives its URL and token from the active profile. Nothing else you configure (env vars, GitHub secrets, `.env`) carries a JFrog credential.
   ```bash
   jf c add poc-admin --interactive
   #   Server URL:      https://YOUR-TENANT.jfrog.io
   #   Authentication:  Access Token
   #   Access token:    <paste an admin access token>
   jf c use poc-admin
   jf rt ping    # must return OK before continuing
   ```
3. **Run environment setup end-to-end:**
   ```bash
   cd setup
   ./00-run-all.sh
   ```
   Runs a read-only collision check against your JFrog tenant first — if any resource under the chosen `POC_APP_NAME` prefix already exists, the pipeline stops and offers three options (change prefix, teardown, or re-run with `--reuse-existing`). On a clean tenant it proceeds through all four setup phases without stopping.
4. **Wire GitHub Actions:**
   ```bash
   gh auth login                              # once, for `gh secret set` in step 3
   ./04-setup-oidc.sh <your-github-org>/<your-repo>
   ```
   Step 3 of `00-run-all.sh` (`03a-setup-signing-key.sh`) already generated an ed25519 keypair, registered the **public** half with the JFrog Evidence trust store, and pushed the **private** half to your GitHub repository as the `POC_EVD_SIGNING_KEY` secret via `gh secret set`. You never see or touch the key material. The OIDC script then creates three JFrog integrations and prints the GitHub Environment values you configure in the Web UI.
5. **Push and watch:**
   ```bash
   git push
   ```
   The `build` workflow will run. When it finishes, use the GitHub Actions UI to trigger `promote-dev-to-qa`, then `promote-qa-to-prod`. The second-to-last requires manual approval in the `qa` GitHub Environment; the last requires manual approval in `prod`.

## Design principles

1. **JFrog CLI first.** Every setup and CI step uses `jf` commands. Raw REST is only used where the CLI does not yet expose the feature (documented inline with a `# CLI-gap:` comment).
2. **No secrets in GitHub.** All auth is OIDC. The only GitHub secret you set is `JF_URL`.
3. **Least privilege per stage.** The dev-stage OIDC identity literally cannot promote — its JFrog user has no permissions on the qa or prod repos.
4. **Deterministic naming.** Every JFrog object is prefixed with the application name so multiple POCs can co-exist in one instance.
5. **Idempotent scripts.** Rerun any setup script; existing objects are detected and skipped, not duplicated.
